# Flag-mask experiments (2026-11-14): results and recommendation

Run on EC2 in isolated worktrees with separate caches (live server untouched). Raw output follows the summary.

## Summary

| | C (current mask) | A (unmask only where OVERFLOW/NONLINEAR) | B (unmask TRANSIENT/SUR_ERROR everywhere) |
|---|---|---|---|
| M5 motion validation | 4/4 pass | 4/4 pass, **identical to C** | 4/4 pass, Barnard D3 false candidates 6 -> 0 |
| Barnard D6 single frames with full aperture | 3 / 58 | 3 / 58 | **50 / 58** |
| Barnard spectrum points (failed) | 4 (352) | 4 (352) | 105 (251) |
| RW Aur spectrum points (failed) | 146 (190) | 146 (190) | **299 (37), now cached** |
| eps Ind B spectrum | 338 (108), not cached | same as C | **396 (50), now cached** |
| WISE 0855 spectrum | 197 (61), not cached | same as C | 205 (53), still just over the 20% limit |
| R Dra D6 single frames with full aperture | 0 / 573 | 0 / 573 | 0 / 573 |

Findings:
- **A is a no-op.** Only 116 of 2,755 TRANSIENT/SUR_ERROR pixels in Barnard's frames (4%) also carry OVERFLOW/NONLINEAR; 21% are within 2 px of a saturated pixel. The flag marks a broad region around the bright star, not just its saturated core.
- **B passes the acceptance gate** (4/4, no new false candidates; Barnard D3 goes from 6 false candidates to 0) and restores the bright cores, so RW Aur and eps Ind B spectra now cache.
- **R Dra is a separate problem, not a mask problem.** In 193 of 200 raw R Dra frames the IMAGE and VARIANCE are NaN across the 2 px aperture in the delivered files themselves. Its core is saturated out of the L2 data. No mask change can recover it. Ideas: photometry on the PSF wings (an annulus of about r 3-6 px) for the light curve, or label R Dra spectra and light curves as unavailable.
- Barnard's spectrum still fails 70% of points even with B (other detectors), and WISE 0855 sits at 20.5% (limit 20%).
- **Definitions now read** (SPHEREx Explanatory Supplement v1.0, Table 9 p.26; nonlinearity section p.22): TRANSIENT = a transient (e.g. cosmic ray) detected during the ramp, and also charge spillover (bloom) from very bright neighbours, "the onset of such spillover can trigger TRANSIENT flagging". SUR_ERROR = an onboard processing consistency bit; with TRANSIENT or OVERFLOW it marks an early transient/overflow. Flagged pixels are not invalid but less accurate: TRANSIENT pixels get an *estimated* nonlinearity correction, SUR_ERROR pixels get *none*. So B is justified for bright-star cores, but those fluxes carry an extra systematic error (likely biased low) of unknown size. Spectrum plots now mark such points as hollow.
- **R Dra follow-up (done):** its delivered core is NaN to about 2 px and finite from 3 px, so spectra and light curves now fall back automatically to PSF-wing ring photometry (r 3-6 px). Relative flux only.

Recommendation: adopt B in `FLAG_BITS_BAD` (remove bits 0 and 2), bump `index.data_version()`, re-run precompute; treat R Dra separately. Not applied: needs approval.
